# dsc-vfs-solvent v2.2

Клиент для **децентрализованного хранения данных** в публичных сетях и службах.
Сейчас поддерживаются протоколы **FTP**, **FTPS**, **SFTP** и **IMAP**.

## Как это работает

1. Файл читается **часть за частью** (chunk, по умолчанию 1 МБ) — целиком в
   оперативную память не загружается.
2. Каждая часть шифруется **AES-256-CFB** со случайным паролем.
3. Части распределяются по доступным учётным записям хранилищ
   (FTP/FTPS/SFTP/IMAP).
4. Шифрование/отправка и скачивание/расшифровка выполняются **многопоточно**
   (до 16 потоков), в памяти находится ограниченный буфер частей.
5. При восстановлении части скачиваются, расшифровываются, записываются на
   свои места и проверяется контрольная сумма (SHA-256).

## Многопользовательность и авторизация

Система поддерживает **несколько пользователей**:

* Логин пользователя — **адрес электронной почты**. При регистрации на e-mail
  отправляется одноразовый код подтверждения; без его ввода вход невозможен.
* Пароли пользователей хранятся как HMAC-метки (PBKDF2 + HMAC-SHA256).
* Доступ выдаётся по **Bearer-токенам** (срок жизни 30 дней, хранится только хеш).
* Пользователь видит и управляет **только своими** файлами и аккаунтами
  хранилищ — изоляция данных на уровне БД (user_id).
* Пользователь может **сменить пароль** (требуется знание текущего) и
  **снять регистрацию** (удалить аккаунт со всеми файлами; части файлов во
  внешних хранилищах уничтожаются).
* **Восстановление пароля**: если пароль забыт, сервер генерирует случайный
  пароль и отправляет его на e-mail. При следующем входе система потребует
  сменить пароль. Внимание: после восстановления пароля ключ пользователя
  пересоздаётся, поэтому пароли FTP/IMAP-аккаунтов нужно ввести заново.
* Пароли FTP/FTPS/SFTP/IMAP-аккаунтов шифруются **ключом пользователя**
  (AES-256-GCM). Ключ пользователя хранится на сервере только в обёрнутом
  виде (`key_cipher` — ключ, зашифрованный производным от пароля ключом).
* Ключ пользователя передаётся на сервер зашифрованным открытым ключом
  сервера (RSA-OAEP, заголовок `X-VFS-Key`); сервер расшифровывает его,
  использует в рамках запроса и кэширует в памяти (TTL 15 минут), в БД
  открытый ключ не сохраняется.
* **Администрирование**: первый зарегистрированный пользователь становится
  администратором. Только администратор может банить/разбанивать
  пользователей (`/api/admin/users/...`) и просматривать список пользователей
  с поиском по имени (`GET /api/admin/users?q=...`). Администратор не может
  забанить другого администратора или самого себя. Забаненный пользователь
  не может войти и использовать токены. У бана фиксируется дата установки
  (`banned_at`); бан действует до конца месяца установки и снимается
  **автоматически** в первый день следующего месяца (даже если до конца
  месяца оставался 1 день) — при попытке входа, использовании токена или
  просмотре списка пользователей администратором.
* При удалении аккаунта хранилища все части файлов, размещённые в нём,
  автоматически переносятся в другие доступные аккаунты пользователя.

## Требования

* Python >= 3.11
* PostgreSQL (схема создаётся автоматически при первом запуске)
* Доступ к FTP/FTPS-серверу, SFTP-серверу и/или IMAP-почтовому ящику
* Для SFTP дополнительно устанавливается библиотека `paramiko` (автоматически)

## Установка

```bash
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -e .
```

## Быстрый старт одной командой

Проект собирается и запускается одной командой (Python + npm-зависимости
устанавливаются и веб-интерфейс собирается автоматически):

```bash
python run.py
```

После запуска откройте <http://127.0.0.1:8000/>.

## Запуск через Docker (с PostgreSQL)

В репозитории есть `Dockerfile` и `docker-compose.yml`: приложение и
PostgreSQL поднимаются одной командой, веб-интерфейс собирается внутри
образа.

```bash
# Собрать и запустить (фоном):
docker compose up -d --build

# Просмотр логов:
docker compose logs -f app
```

После запуска откройте <http://127.0.0.1:8000/>.

Конфигурация через переменные окружения (можно указать в `.env` рядом с
`docker-compose.yml`):

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `POSTGRES_USER` | `dsc` | Пользователь PostgreSQL |
| `POSTGRES_PASSWORD` | `dsc` | Пароль PostgreSQL |
| `POSTGRES_DB` | `dsc_vfs_solvent` | Имя базы данных |
| `APP_PORT` | `8000` | Порт, публикуемый наружу |
| `DB_HOST` / `DB_PORT` | `db` / `5432` | Хост/порт БД (для app) |
| `SMTP_HOST` / `SMTP_PORT` | пусто / `587` | SMTP для писем (если пусто — лог-режим) |
| `SMTP_USER` / `SMTP_PASSWORD` | пусто | Учётные данные SMTP |
| `SMTP_FROM` | `noreply@ashatrov.ru` | Отправитель писем |

Данные PostgreSQL хранятся в volume `pgdata`, конфиг и RSA-ключи —
в volume `appdata` (`/app/config`). Остановка с удалением контейнеров:
`docker compose down` (volumes при этом сохраняются; чтобы удалить и их —
`docker compose down -v`).

## REST API сервер

* Веб-интерфейс: <http://127.0.0.1:8000/>
* Документация API (Swagger): <http://127.0.0.1:8000/docs>

### Основные эндпоинты

| Метод | Путь | Описание |
| --- | --- | --- |
| POST | `/api/auth/register` | Регистрация по e-mail (отправляет код подтверждения) |
| POST | `/api/auth/verify` | Подтвердить e-mail кодом из письма, получить токен |
| POST | `/api/auth/login` | Вход, получение токена |
| POST | `/api/auth/logout` | Выход, отзыв токена |
| POST | `/api/auth/change-password` | Сменить пароль (нужен текущий) |
| POST | `/api/auth/forgot-password` | Восстановление пароля (случайный на e-mail) |
| POST | `/api/auth/delete-account` | Удалить аккаунт со всеми файлами |
| GET | `/api/auth/me` | Текущий пользователь |
| GET | `/api/auth/public-key` | Открытый RSA-ключ сервера |
| POST | `/api/auth/key` | Передать зашифрованный ключ (X-VFS-Key) |
| GET | `/api/admin/users?q=` | Список пользователей с поиском по имени (админ) |
| POST | `/api/admin/users/{id}/ban` | Забанить пользователя (админ) |
| POST | `/api/admin/users/{id}/unban` | Разбанить пользователя (админ) |
| GET | `/api/accounts` | Список аккаунтов (своих) |
| POST | `/api/accounts` | Добавить аккаунт |
| PATCH | `/api/accounts/{id}` | Обновить аккаунт |
| DELETE | `/api/accounts/{id}` | Удалить аккаунт (части файлов переносятся в другие аккаунты) |
| POST | `/api/files` | Загрузить файл (multipart, потоково) |
| GET | `/api/files` | Список файлов (своих) |
| GET | `/api/files/{id}` | Информация о файле |
| GET | `/api/files/{id}/nodes` | Части файла |
| GET | `/api/files/{id}/download` | Скачать файл (потоково) |
| DELETE | `/api/files/{id}` | Удалить файл |

Все защищённые эндпоинты требуют заголовок:

```
Authorization: Bearer <token>
```

## Сборка веб-интерфейса (Gulp + TypeScript)

Веб-интерфейс собирается из исходников в `src/dsc_vfs_solvent/web/src/`
в готовые минифицированные файлы `src/dsc_vfs_solvent/web/dist/` с помощью
**Gulp**: TypeScript (строгий режим) → JS → Terser, CSS → PostCSS
(autoprefixer + cssnano), sourcemaps. **Bootstrap 5** копируется локально
из `node_modules/bootstrap/dist/css/bootstrap.min.css` (без CDN) и
подключается отдельным `<link>` перед кастомными стилями.

```bash
npm install        # установить dev-зависимости (gulp, typescript, bootstrap и плагины)
npm run typecheck  # проверка типов TypeScript без сборки
npm run build      # собрать styles.min.css, bootstrap.min.css и app.min.js (+ sourcemaps)
npm run watch      # автоматическая пересборка при изменении исходников
npm run clean      # удалить каталог dist
```

После сборки `index.html` подключает `/static/dist/styles.min.css`
и `/static/dist/app.min.js`. Каталог `dist` в git не хранится
(генерируется сборкой); при установке пакета собранные файлы включаются
в wheel.

## Документация API и Postman

* **OpenAPI-спецификация**: `docs/openapi.yaml` — описание всех эндпоинтов,
  схем и схемы авторизации (Bearer). Можно импортировать в Swagger Editor,
  Insomnia, Stoplight и т.п.
* **Коллекция Postman**: `docs/postman_collection.json` — готовые запросы
  для авторизации, аккаунтов и файлов. Переменные коллекции:
  `baseUrl`, `token` (заполняется автоматически), `username`, `password`,
  `accountId`, `fileId`.

## Автотесты

Тесты находятся в `tests/` и используют pytest + httpx (TestClient FastAPI).
Для тестов требуется **запущенный PostgreSQL-сервер**: DSN задаётся переменной
окружения `DATABASE_URL` (например,
`postgresql+psycopg://postgres:postgres@127.0.0.1:5432/postgres`). Каждый тест
работает в отдельной изолированной схеме, которая удаляется после завершения.
Внешние хранилища не требуются: для файловых операций используется
in-memory fake-драйвер.

```bash
pip install -e ".[dev]"
export DATABASE_URL="postgresql+psycopg://postgres:postgres@127.0.0.1:5432/postgres"
pytest
```

Покрытие:
* `test_auth.py` — регистрация, вход, выход, `/auth/me`, изоляция токенов;
* `test_accounts.py` — создание/список/обновление/удаление аккаунтов,
  изоляция между пользователями;
* `test_files.py` — запись/чтение файлов, перенос частей при удалении
  аккаунта (`migrate_account`), ошибка загрузки без аккаунта;
* `test_admin.py` — бан/разбан, запрет бана администратора и самого себя,
  поиск пользователей по имени.

## Конфигурация

По умолчанию настройки хранятся в `config/settings.json` (переменная окружения
`DSC_VFS_CONFIG` позволяет указать другой путь). Подключение к PostgreSQL
задаётся отдельными полями: `db_host`, `db_port`, `db_user`, `db_password`,
`db_name`. Таблицы и индексы создаются автоматически при первом запуске.
Серверный RSA-ключ для защиты ключей пользователей (RSA-OAEP) генерируется
автоматически при первом запуске.
